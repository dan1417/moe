## 3. What is NOT the mechanism (checked)
- Memorizing the eval windows: the pools are 14.4 T tokens (pretrain 4.7 T, math 4.0 T, txt360 3.1 T, code 2.5 T).
- Memorizing the long documents: the pinned index is 150+ GB of fragment pointers (tens of millions of documents).
- Distillation (user: proven not to work), head / router / calibration tweaks (all <= 1e-4), public-king merges
  alone (ceiling +0.0002..+0.0005 vs a fresh king; every public step is inside the king within a day).

## 4. The race for a specialist crown
A new MAIN king X beats the old specialist kings by 0.0025-0.0045 on their mixes, so X itself clears every specialist
bar. 5DALwjE4 submits X (plus noise) to MATH / TEXT at the same time as X; the evaluator serializes them (MATH came
2 h, TEXT 3 h after X). On CODE their X-copy failed twice (+0.00204 / +0.00206, LCB 0.00196 / 0.00198 < 0.002) and
holly (M45 + noise, 6 h later) took it with +0.00223. Our download + ingest of a king takes 6 min (no re-basing
needed for 5DALwjE4's recent kings); a merge round ~1 h; staging (permute + verify + HF backup) ~30 min; upload to
R2 and the validator's own 1 h duel on top. We cannot beat a submission that was ready before X was crowned, but we
can beat one that fails, and any **X + a real delta of ours** beats X + noise by the delta.

- The step grows like sqrt(hours) and consecutive steps are aligned (cos +0.3..+0.45): **one continuous run, snapshotted
  whenever it is 0.003 ahead** (their repo numbers count every upload: -77 .. -105).
- |d| is Gaussian per weight (q90/q10 = 13), attention norms shrink 0.6-1 % per step and ~2 % over the 78-h double
  step: **many small AdamW updates with weight decay (~0.1)**; lr about 2e-6..1e-5, 10-40k updates per king, i.e.
  **0.25-1M-token batches** (their specialist touch-ups: median move 3e-5 = 5-10 such steps). Experts, shared experts,
  lm_head (+0.7-1.3 % per step) and embeddings grow; routers 0.7 % (frozen). Layer 5's attention moves as much as
  layer 30's: **all layers trained**.

  consecutive steps share a direction, M44 a merge. What they do NOT pin down: lr and N separately (only lr x sqrt(N) and

## 6. What was launched (2026-10-14 05:01 UTC, `autopilot_text`, run `text_ap_10140501`)
Start M45 (= TX6 = MA2 functionally). lr 5e-6 constant (warmup 100, no decay), AdamW wd 0.1, only routers frozen
(110.3B trainable: all layers, embeddings, lm_head), 4 x 2 x 8 x 8 192 = 0.52M tokens per step, EMA 0.99, fp32
masters, 8-bit Adam offloaded between steps, exact state every 200 steps, val (1 024 seqs) every 50, screens on all
four competitions every 1 000 steps on 4 800 seqs, 10 000-step segments (~5 B tokens). Data: text_mix_v1 (text /
math / code 70/15/15 of the splits, half 8 192-token documents, half four EOS-separated windows); the MAIN mixes
(all five sources at the eval proportions, same shape) join the diet as they are built (`build_main_pools.sh`,
`REQUEST_RELAUNCH` resumes the exact state with the new pools). The autopilot's LR policy is `wsd` = hands off.
Merge mode on every new TEXT or MAIN king: candidates on the competition's king and on the newest MAIN king X
(soups, transplants of our delta, our checkpoints as is, the public campaign's best), scored on all four
competitions, chosen on an independent sample; a material candidate that clears a competition's bar on B is
confirmed on full B + C and staged (never a king as is).

First hour (paired held-out val, 1 024 seqs, vs the start 1.16867): step 50 EMA -0.00004 / raw +0.00019; step 100
EMA +0.00015 / raw +0.00109; step 150 EMA +0.00039 / raw +0.00210, all three sources up alike. The raw weights climb
toward the noise floor of constant-LR training at lr 5e-6 with 0.5M-token batches (the stability gap of Gupta et al.
2023, which they measured even for same-data re-warming); the EMA 0.99 only lags the raw curve by ~100 steps, it
does not remove a floor. So checkpoints are judged after a **cool-down**: `REQUEST_ANNEAL {"k": 100}` cosines the
LR to 5e-7 over 100 steps on a copy, the cooled checkpoint is screened, the pre-anneal state is restored and the
constant-LR run continues (min_lr_frac 0.1 enables it from the next relaunch; the schedule itself never decays).
The step-1 000 screen compares the plain EMA checkpoint with the cooled one.

Result of the first cycle (10:50 UTC): the hot EMA checkpoint at step 1 000 screened MATH -0.0026 / CODE -0.0032 /
TEXT -0.0033 vs the kings (4 800 seqs; MAIN invalid: the loss cache had filed the checkpoint under M45's digest via a
copied king_info.json, fixed in 0388ac9). By component: TEXT windows -0.0036, long documents +0.0006 (4k-8k bucket
+0.0034); MATH windows -0.0028, long -0.0006 (4k-8k +0.0020); CODE windows -0.0032, long -0.0028. The 300-step
cool-down (lr 5e-6 -> 5e-7, steps 1051-1351) took the raw held-out loss from +0.0050 to only +0.0041 (step 1300):
the loss is not a removable noise floor, the run drifted to a worse point for the 2 048-token windows (91 % of every
score) while learning the long-document component, the same erosion c8/c9 showed at 100x smaller amplitude.
The cooled step-1400 checkpoint screened MAIN -0.0032 / MATH -0.0029 / CODE -0.0036 / TEXT -0.0037 (11:41 UTC): no
better than the hot one. Conclusion: 8 192-token rows are out; constant lr 5e-6 at 0.5M-token steps moves the model
too fast relative to its signal. The lineage was retired at step 1 400 (state archived under
/data/teutonic/autopilot/text_lr5e6_*). Next lineage (started by `decide_after_cooldown.sh` after the step-1400 screen): from M45, 2 048-token
window rows only (text + MAIN window pools, all five sources), lr 2e-6, 16 x 4 x 8 x 2 048 = 1M tokens per step.

Gates (paired held-out screens vs M45, cooled and plain checkpoints; the training loss decides nothing): step 2 000 (~6 h) is a
harm check: no negative drift (>= -0.0001 on the MAIN mix at 4 800 seqs, SE ~7e-5). The decisive gate is step 8 000
(~1 day): >= +0.0007 on the MAIN mix, the lower bound of the hypothesis (their king = N steps at this lr: +0.0033 x
8 000 / N for N in 8k..40k). A miss stops the lineage; there is NO automatic fallback to a higher LR (the weights pin
lr x sqrt(N), not lr: 3e-5 x 1-2.5k steps fits the same displacement; a miss at 5e-6 means the decomposition is
wrong, to be re-thought, not re-run hotter).
Targets: CODE and MATH first (X + our delta beats X + noise; a +0.0006 delta on those mixes makes the crown
un-copyable), TEXT (needs +0.0023), MAIN when the delta reaches a king-sized step (+0.0036).

## 7. Gradient signal vs noise (14:19 UTC) -> 16.8M-token steps
Run 2 (text_ap_10141144: lr 2e-6, 1M-token steps of 2 048-token windows from M45) sat at its start for 318 steps
(EMA +0.00005, raw +0.0003, creeping up). The trainer now logs |g| of the first micro-step (b = 128 seqs) next to the
full step's (B = 4b = 1.05M tokens); per McCandlish et al. 2018, |G|^2 = (K|g_B|^2 - |g_b|^2)/(K-1) and
tr(Sigma)/B = (|g_b|^2 - |g_B|^2)/(K-1) (`scripts/train/grad_snr.py`). 40 steps: |g_b| 0.3575, |g_B| 0.1820
(ratio 1.97; pure noise = 2.0), |G|^2 = 1.5e-3 +- 6.4e-4, tr(Sigma)/B = 3.16e-2: the population gradient is 4.7 % of
each step's gradient energy, B_noise = tr(Sigma)/|G|^2 ~ 21M tokens (12M..100M+). Every run of ours (0.5-4.2M tokens
per step) trained 5-40x below the noise scale: updates were 95 % noise, which is why held-out loss drifted up and why
lowering the LR only slowed the drift.
Run 3 (from M45, 14:25 UTC): 16 x 64 x 8 x 2 048 = 16.8M tokens per step (~5.5 min), lr 8e-6 (square-root scaling
from 2e-6 at 1M), warmup 10, wd 0.1, EMA 0.9, val every 5 steps, checkpoint + state every 10, screens every 40.
Gate at step 40 (0.67B tokens): EMA held-out <= start - 0.0003 or MAIN-mix screen >= +0.0003 vs M45, else stop.
